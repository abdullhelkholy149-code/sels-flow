# ملخص المرحلة 0 — Bootstrap

**الحالة: مُنفَّذة في الكود، ⛔ غير مُتحقَّق منها بالتشغيل.**

لم يكن على الجهاز Node.js أو Docker أو PostgreSQL وقت التنفيذ، لذلك لم يُنفَّذ
تثبيت الحزم ولا فحص الأنواع ولا الفحص الشكلي ولا الاختبارات ولا الترحيلات. كل ما
يحتاج تشغيلاً مُجمَّع في `PROGRESS.md` تحت عنوان بانتظار التحقق، وهذه القائمة
تكررها عملياً.

## ما تم بناؤه

### البنية

| الملف | الغرض |
|---|---|
| `package.json` | سكريبتات التطوير والفحص والترحيلات وبذور البيانات |
| `tsconfig.json` | TypeScript صارم مع منع الفهارس غير المؤكدة |
| `eslint.config.mjs` | ESLint مسطّح مع قواعد Next |
| `vitest.config.ts` | اختبارات الوحدة بلا قاعدة بيانات |
| `vitest.integration.config.ts` | اختبارات التكامل على PostgreSQL حقيقي |
| `playwright.config.ts` | هيكل اختبارات المتصفح بتوقيت القاهرة ولغة عربية |
| `scripts/ci.mjs` | نفس سلسلة الفحص المستخدمة في خط الأنابيب |

### الحاوية والتشغيل

| الملف | الغرض |
|---|---|
| `Dockerfile` | ثلاث مراحل على أساس node 22 من نوع bookworm slim |
| `docker-compose.yml` | خدمات postgres و migrate و app و worker |
| `docker-compose.test.yml` | قاعدة بيانات اختبارات مؤقتة على منفذ مختلف |
| `.env.example` | كل المتغيرات، بلا أي سر حقيقي |

### قاعدة البيانات

ملف `prisma/schema.prisma` يحتوي أساس المرحلة الأولى:

- جدول المستخدمين بالأدوار وحالة القفل وإجبار تغيير كلمة المرور
- جدول إعدادات الشركة بصف واحد فقط، ويشمل كل قيم العمل الافتراضية
- جدول سجل التدقيق، لا يُعدَّل ولا يُحذف
- جدول عدّادات المستندات: عدّاد لكل نوع في كل سنة، أساس الترقيم المتصل
- جدولا المندوبين والعملاء كقوالب أولية تتوسع في المرحلة الثالثة

### الأمان والحوكمة

- تحقق صارم من متغيرات البيئة، ويرفض الأسرار النمطية في الإنتاج
- سجلات JSON مع إخفاء الأسرار وحقل معرّف الطلب
- عميل قاعدة بيانات واحد، ودالة معاملة واحدة إلزامية لكل تغيير مالي أو مخزني
- توجيه اللغة عبر الوسيط، وترويسات أمان أساسية في إعدادات Next

### الواجهة

- عربية افتراضية من اليمين إلى اليسار، وإنجليزية جاهزة بنفس المفاتيح
- رموز تصميم في Tailwind، وخصائص منطقية بدل اليمين واليسار
- صفحة ترحيب، وتبديل لغة، وتذييل، وبطاقات
- تطبيق قابل للتثبيت: بيان أيقونات وأيقونة عادية وأخرى قابلة للقص
- نقطة فحص الصحة ترجع رمز 200 أو 503 حسب قاعدة البيانات

### الاختبارات

| الملف | ما يغطيه |
|---|---|
| `tests/unit/i18n.test.ts` | تطابق مفاتيح العربية والإنجليزية، وعدم وجود قيم فارغة |
| `tests/unit/format.test.ts` | التقريب نصف للأعلى، خانتان للمال، ثلاث للكميات، أرقام غربية، تاريخ القاهرة |
| `tests/unit/env.test.ts` | القيم الافتراضية، ورفض الأسرار القصيرة أو النمطية، ورفض مزوّد واتساب التفاعلي في الإنتاج |
| `tests/unit/conventions.test.ts` | ثوابت المال والكمية والمنطقة الزمنية والعملة |

### التوثيق

خطة المراحل، وسجل التقدّم، وسجل القرارات، ودليل التشغيل، وملف الفاتورة الإلكترونية.

## ما لم يُنفَّذ عمداً في هذه المرحلة

- لا ملف ترحيل مكتوب باليد. القرار D-006: التوليد آلي بعد تثبيت الأدوات
- لا بوابة فاتورة إلكترونية. المرحلة الثانية عشرة، وهي ممنوعة بلا تعليم صريح
- لا بذور بيانات كاملة. البذور الكاملة تأتي مع المرحلة الثالثة
- لا اختبارات تكامل بعد، لأن المرحلة صفر لا تنفذ قاعدة عمل تستحق اختباراً

## المخاطر المتبقية بعد التثبيت

1. **تطابق إصدارات الحزم**: الأرقام مثبتة بإصدارات، وقد تحتاج مواءمة بعد أول
   تثبيت إذا ظهر تعارض بين إصدارات.
2. **شكل تنسيق الأرقام**: الاختبارات تفترض الفاصلة والنقطة مع الإعداد
   `ar-EG-u-nu-latn`. إن اختلف الناتج على إصدار ICU، يُعدّل الاختبار لا الكود.
3. **إعداد الفحص الشكلي المسطّح**: قواعد Next تُحمَّل عبر الجسر المقدم من
   eslint. إن فشل الإقلاع، البديل إضافة إضافة Next مباشرة أو الرجوع لأمر Next.4. **نظام التشغيل**: التطوير هنا على ويندوز، بينما صورة الحاوية لينكس. أي أمر
   يعتمد على الصدفة سيُختبر على الحاوية لا على جهاز التطوير.
