# خطة التنفيذ — SalesFlow

نظام توزيع منتجات عبر مناديب بيع إلى عملاء (مصر). خطة تنفيذ مُقسّمة لمراحل، كل مرحلة لها
معايير قبول مُغلقة، ولا تبدأ مرحلة قبل اجتياز التي قبلها.

المصدر الإلزامي للمواصفات: `opencode-sales-rep-app-prompt.md`.
سجل التقدّم الفعلي: [`PROGRESS.md`](./PROGRESS.md). القرارات: [`DECISIONS.md`](./DECISIONS.md).

---

## 0. قواعد العمل الثابتة

| القاعدة | التطبيق العملي |
|---|---|
| المال `NUMERIC(14,2)` + `decimal.js` | ممنوع أي `number` في حساب مالي أو كمية |
| الكميات `NUMERIC(14,3)` | 3 خانات عشرية |
| تقريب half-up لرقمين **لكل سطر فاتورة** | المجموع = مجموع السطور المدوّرة |
| الأختام بالـ UTC، العرض بتوقيت `Africa/Cairo` | تاريخ ميلادي وأرقام غربية |
| حذف ناعم فقط للبيانات الأساسية (`deleted_at`) | المستندات المالية والمخزنية لا تُحذف ولا تُعدّل بعد الترحيل |
| كل معاملة مالية/مخزنية داخل `SELECT ... FOR UPDATE` | مع قيود `CHECK` كشبكة أمان ثانية |
| كل قاعدة عمل لها اختبار آلي | لا تُعتبر المرحلة منتهية قبل تغطية القاعدة |
| كود ومعرّفات وتعليقات بالإنجليزي، واجهة المستخدم بالعربي | `next-intl` — لا نصوص ثابتة داخل المكونات |

## 1. خريطة المراحل

| المرحلة | المحتوى | معيار القبول |
|---|---|---|
| **0** Bootstrap | الهيكل، Docker Compose، Prisma، i18n RTL، health، CI، التوثيق | `docker compose up` يعطي صفحة عربية RTL + الاختبارات خضراء |
| **1** Auth/RBAC/Audit | مستخدمون، أدوار، دخول وقفل، خريطة صلاحيات، طبقة وصول بنطاق، سجل تدقيق، إعدادات | اختبارات النطاق تنجح + محاولات الدخول الفاشلة مقيّدة ومسجّلة |
| **2** الكتالوج والتسعير | فئات، وحدات، منتجات، قوائم أسعار، سعر ساري بالتاريخ، ضريبة لكل منتج | دقة السعر بالتاريخ مُختبَرة + CRUD للأدمن |
| **3** المناديب والعملاء | مناديب، عملاء، فئات، تاريخ الإسناد، حساب العميل من الزيارة، شروط السداد، رصيد افتتاحي | المندوب يرى عملاءه فقط + إجبار تغيير كلمة المرور أول مرة |
| **4** المخازن والعهدة | أرصدة، دفتر حركات غير قابل للتعديل، إيصالات، أوامر صرف بعهدة مع إشعار المندوب، مرتجع للمخزن، جرد وفروق، تنبيه انخفاض الرصيد | مستحيل أن يصبح المخزون سالباً (اختبار تزامن) + كل رصيد قابل للتشتق من الدفتر |
| **5** الطلبيات | كتالوج وسلة، تقديم، تعديل/اعتماد/رفض المندوب، فحص مخزون وسداد، طابور تجاوز السداد، حجز، تسليم بـ GPS، تاريخ الحالات | كل اختبارات آلة الحالات + اختبار منع البيع الزائد + اختبارات السداد |
| **6** الفواتير والمال | إصدار فاتورة عند التسليم، ترقيم متصل، PDF عربي RTL، تحصيل وتخصيص، دفتر العميل، كشوف وتقادم، تسليم نقدية المندوب | اختبار ترقيم تحت التوازي + توازن الدفتر (أرصدة الفواتير المفتوحة − ائتمان غير موزّع) + PDF عربي سليم |
| **7** الزيارات والمسارات والأهداف | قوالب وخطط، حضور/انصراف مع Geoflag، أهداف ونِسب achievement محسوبة من البيانات | اختبار مسافة الـ Geofence + achievement مطابق للتقارير |
| **8** المرتجعات | تدفق ثلاثي، صور، حالة الاستلام، إشعار دائن | حدود الكميات + قاعدة نافذة الإرجاع + أثر المخزون والدفتر مُختبَر |
| **9** التقييمات والإشعارات | تقييم اتجاهين بقواعد ظهور، إشعارات داخل التطبيق، WhatsApp مع outbox ومحاولات، قوالب، تذكيرات يومية | كل حدث في §5.11 ينتج الإشعار الصحيح + لا إرسال بدون موافقة |
| **10** اللوحات والتقارير | لوحات أدوار + كل تقارير §9 مع تصدير | مطابقة أرقام التقارير لمستندات المصدر |
| **11** التصلب | E2E كامل، قائمة أمان، مراجعة فهارس وأداء، تمرين نسخ احتياطي، توثيق نشر، تفعيل STOREKEEPER/ACCOUNTANT | E2E أخضر + `docs/OPERATIONS.md` مكتمل |
| **12** الفاتورة الإلكترونية | تنفيذ `EInvoiceGateway` على توثيق مصلحة الضرائب الرسمي | **لا يبدأ إلا بتعليم صريح** |

## 3. ترتيب التنفيذ الفعلي وداخل كل مرحلة

المراحل تُقسّم داخلياً إلى "شرائح (slices)" مستقلة قابلة للاختبار، كل شريحة تمر
بنفس المعيار. الترتيب المقترح للمراحل الكبيرة:

**المرحلة 1** ← مستخدمون وRoles ← login/lockout ← تغيير كلمة المرور ← خريطة
الصلاحيات ← طبقة الوصول ذات النطاق ← audit log ← إعدادات الشركة.

**المرحلة 4** ← `warehouses`+`stock_balances` ← دفتر `stock_movements` ← إيصالات
استلام ← أوامر صرف بعهدة + إشعار المندوب ← مرتجع للمخزن ← جرد وفروق ← تنبيه
انخفاض الرصيد.

**المرحلة 5** ← آلة الحالات ← الكتالوج والسلة ← التقديم (مع idempotency) ← تعديل
المندوب ← الاعتماد + الحجز + فحص السداد ← طابور التجاوز ← التسليم + الفاتورة.

**المرحلة 6** ← ترقيم المستندات المتصل ← الفاتورة والسطور ← PDF عربي ← التحصيل
والتخصيص ← دفتر العميل ← الكشف والتقادم ← تسليم النقدية.

## 4. مخاطر معروفة وخطة التعامل

| الخطر | التعامل |
|---|---|
| **لا توجد أدوات على الجهاز (Node/Docker/Postgres)** | الكود يُكتب الآن، والتحقق (typecheck/lint/tests/migrations) معلّق حتى تثبيت Node. كل ما يحتاج تحققاً مُجمَّع في `PROGRESS.md → بانتظار التحقق` |
| ترقيم متصل تحت التوازي | عدّاد مقفل `SELECT ... FOR UPDATE` داخل نفس معاملة الفاتورة + اختبار تزامن |
| المخزون السالب | `CHECK (on_hand >= 0 AND reserved >= 0 AND reserved <= on_hand)` + حجز قبل البيع + اختبار توازٍ |
| تجاوز السداد | حساب exposure داخل المعاملة + طابور تجاوز للإداري مع تسجيل السبب |
| الشطب بالفروق | إشعار دائن + فاتورة جديدة، لا تعديل فاتورة مُصدَرة |
| أرقام/تواريخ عربية معطوبة | كل الأرقام غربية، منطق كامل via `Intl` + خط عربي في PDF عبر Chromium |
| خصوصية الموقع | يُلتقط GPS فقط عند إجراءات صريحة، ويُذكر ذلك في الواجهة |
| تخمين متطلبات الفاتورة الإلكترونية | ممنوع تخمين أي حقل أو endpoint — `TODO(verify-with-official-docs)` فقط |
